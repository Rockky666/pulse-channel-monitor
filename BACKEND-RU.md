# Подключение бэкенда Pulse к Cloudflare Workers

Фронтенд: https://rockky666.github.io/pulse-channel-monitor/

Этот бэкенд получает публичные показатели YouTube и до 50 последних видео по кнопке «Обновить YouTube». TikTok и Instagram пока работают вручную: их OAuth-интеграции не реализованы. Группы и полученные метрики по-прежнему сохраняются в браузере, а не в облачной базе; фонового обновления при закрытом сайте нет.

## 1. Создайте Worker из репозитория

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com/) и оставайтесь на тарифе Workers Free.
2. Откройте **Workers & Pages → Create application** и выберите импорт GitHub-репозитория. Если сначала предлагается выбор, нужен **Worker**, а не статический Pages-проект.
3. Подключите GitHub и предоставьте Cloudflare доступ только к репозиторию **Rockky666/pulse-channel-monitor**.
4. Выберите этот репозиторий, ветку **main**.
5. Настройте развертывание:

| Поле | Значение |
| --- | --- |
| Worker / Project name | `pulse-api` |
| Root directory | `/` (корень репозитория; если поле пустое, оставьте пустым) |
| Build command | оставить пустым |
| Deploy command | `npx wrangler deploy` |

6. Нажмите **Deploy** и дождитесь успешного результата.
7. Скопируйте выданный адрес, например `https://pulse-api.example.workers.dev`.

Файл `wrangler.jsonc` уже содержит имя Worker, основной файл и разрешённый адрес фронтенда. Не меняйте имя Worker отдельно от `name` в конфигурации.

Официальные инструкции: [создание через панель](https://developers.cloudflare.com/workers/get-started/dashboard/), [настройка сборки](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/).

## 2. Добавьте два секрета

Откройте созданный Worker → **Settings → Variables and Secrets → Add**. Для обоих значений выберите тип **Secret**.

| Variable name | Что указать |
| --- | --- |
| `YOUTUBE_API_KEY` | ваш ключ YouTube Data API v3 из Google Cloud |
| `PULSE_ACCESS_TOKEN` | отдельная случайная строка минимум из 32 символов; это пароль доступа к вашему API |

Для `PULSE_ACCESS_TOKEN` можно сгенерировать случайный пароль длиной 40 символов в менеджере паролей. Сохраните его у себя. Не используйте пароль Google или GitHub и не помещайте эти значения в репозиторий.

Нажмите **Deploy**, чтобы применить секреты. Google API key и код доступа Pulse — два разных значения.

Текстовая переменная `ALLOWED_ORIGIN` уже задана в конфигурации:

```
https://rockky666.github.io
```

Это origin, поэтому путь `/pulse-channel-monitor/` в неё добавлять не нужно. Если фронтенд позже переедет, измените `vars.ALLOWED_ORIGIN` в `wrangler.jsonc` и разверните Worker снова.

[Официальная инструкция по секретам](https://developers.cloudflare.com/workers/configuration/secrets/).

## 3. Проверьте сервер

Откройте адрес своего Worker с окончанием `/health`:

```
https://pulse-api.example.workers.dev/health
```

Ожидаемый ответ:

```json
{"ok":true,"service":"pulse-api"}
```

Это проверяет доступность сервера. Проверка Google API происходит при обновлении группы на следующем шаге.

## 4. Соедините сайт и сервер

1. Откройте https://rockky666.github.io/pulse-channel-monitor/
2. Перейдите в **Подключения**.
3. В блоке **Подключить YouTube API** вставьте адрес Worker без `/health` и без других путей.
4. Введите **PULSE_ACCESS_TOKEN**, который вы задали на шаге 2. Не вводите сюда Google API key.
5. Нажмите **Сохранить подключение**.
6. Создайте собственную группу и добавьте ссылку YouTube вида `https://www.youtube.com/@имя` или `https://www.youtube.com/channel/UC…`.
7. Откройте группу и нажмите **Обновить YouTube**.

Должны загрузиться просмотры канала, доступное число подписчиков, названия, превью, даты и просмотры до 50 последних видео. Уже добавленные ролики с совпадающей YouTube-ссылкой обновятся без дублирования; версии Instagram/TikTok сохранятся. Ролики за пределами последних 50, уже сохранённые ранее, остаются со старыми просмотрами. Скрытое число подписчиков не восстанавливается API; итог подписчиков в таком случае неполный.

Код доступа Pulse хранится только в памяти вкладки. После перезагрузки страницы введите его снова в «Подключениях». Адрес Worker и данные групп сохраняются локально в браузере.

## Если не получилось

- **Неверный код доступа Pulse**: повторно введите именно значение `PULSE_ACCESS_TOKEN`.
- **Не настроены секреты Worker**: проверьте названия, тип Secret и нажмите Deploy. Минимальная длина кода — 32 символа.
- **Не удалось подключиться**: проверьте адрес Worker, HTTPS, правильность `ALLOWED_ORIGIN` и успешное развертывание.
- **Ошибка доступа к YouTube API**: проверьте, что в Google Cloud включён YouTube Data API v3 и ключ ограничен именно этим API. Worker обращается к Google с сервера, поэтому ограничения ключа по HTTP referrer сайта к этому способу не подходят. Для этого отдельного серверного ключа выбирайте совместимые с серверным размещением ограничения; API restriction оставьте YouTube Data API v3. Ключ остаётся только в секретах Cloudflare.
- **Канал не найден**: используйте актуальный @handle или /channel/UC…; старые ссылки /c/ не поддерживаются.
- **Квота исчерпана**: повторите позже. Не нажимайте обновление многократно подряд.

Рабочие запросы требуют кода доступа и точного origin. Публичный `/health` не раскрывает ключей. Сайт на GitHub Pages публичный; это не делает личные данные из вашего браузера доступными другим посетителям. При использовании личного устройства не передавайте третьим лицам код доступа к API.

## Обновление кода и локальные проверки

Изменения `worker.mjs` в подключённой ветке будут развертываться через Cloudflare Builds. Обычная публикация кода сохраняет секреты Worker; в репозитории им места нет.

Проверки без настоящего YouTube-ключа:

```sh
node --test worker.test.mjs
node --check app.js
```

Тесты используют искусственные ответы API. Реальный доступ к Google проверяется только после вашей настройки секретов.

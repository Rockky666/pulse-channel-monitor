# TikTok Sandbox в Pulse

Фронтенд: https://rockky666.github.io/pulse-channel-monitor/

Готовы: авторизация TikTok, защищенный callback, серверное хранение и обновление токенов, загрузка публичного профиля и до 100 последних видео, отзыв доступа. Работа с настоящим аккаунтом требует Client secret вашего Sandbox и описанной ниже настройки; тесты с искусственными ответами не подтверждают реальный доступ TikTok.

## 1. Настройте Sandbox TikTok

В [Manage apps](https://developers.tiktok.com/) откройте Pulse и переключите Production → Sandbox. Выберите созданный Sandbox.

Client key, уже записанный в конфигурации Worker:

```
sbawgcg7ufolbtr27p
```

Он должен совпадать с Client key именно выбранного Sandbox. Client secret должен быть от этого же Sandbox.

Добавьте продукты **Login Kit** и **Display API**. Добавьте разрешения:

- `user.info.basic` — идентификация и отображаемое имя;
- `user.info.profile` — username и ссылка на профиль;
- `user.info.stats` — подписчики, количество видео и лайков;
- `video.list` — публичные ролики и их показатели.

В **Login Kit → Web → Redirect URI** добавьте строго этот адрес без завершающего слеша:

```
https://pulse-api.gromagnetik.workers.dev/auth/tiktok/callback
```

В **Sandbox settings → Target users → Add account** добавьте свой TikTok-аккаунт. Если их несколько, добавьте каждый отдельно. Пароль вводится на странице TikTok. Нажмите **Apply changes**. Добавление Target users иногда отображается с задержкой.

Для тестирования используется Sandbox. Production review для незавершенного или исключительно личного проекта не подходит; подтверждение домена не означает одобрения приложения.

Официальные инструкции: [Sandbox](https://developers.tiktok.com/docs/en/add-a-sandbox), [Web Login Kit](https://developers.tiktok.com/docs/en/login-kit-web).

## 2. Разверните обновленный Worker

В репозитории есть `worker.mjs`, `tiktok.mjs` и `wrangler.jsonc`. Нужны все три файла: старый Worker только для YouTube не поддерживает эти маршруты.

Если Worker уже подключен к этому GitHub-репозиторию через Cloudflare Builds, дождитесь успешной сборки последнего коммита. Иначе подключите репозиторий по инструкции [BACKEND-RU.md](BACKEND-RU.md). Имя Worker — `pulse-api`, ветка — `main`, корень — репозиторий, команда сборки пустая, Deploy command — `npx wrangler deploy`. Если Worker уже существует, выберите подключение Git-репозитория в его разделе Settings → Build, чтобы обновить именно его.

Для обновления через терминал, если Git-подключение недоступно:

```sh
git clone https://github.com/Rockky666/pulse-channel-monitor.git
cd pulse-channel-monitor
npx wrangler login
npx wrangler deploy
```

Войдите в тот Cloudflare-аккаунт, где находится ваш `pulse-api`. Если каталог уже клонирован, вместо повторного клонирования обновите его через `git pull` и выполните deploy. Конфигурация создает приватное хранилище `TIKTOK_STORE` как SQLite-backed Durable Object. Оно доступно на Workers Free в пределах его лимитов. Не выбирайте Workers Paid только ради подключения этой функции.

Если сборка сообщает несовпадение имени Worker, имя должно быть `pulse-api` и в Cloudflare, и в `wrangler.jsonc`.

## 3. Добавьте секрет в Cloudflare

Откройте **Workers & Pages → pulse-api → Settings → Variables and Secrets → Add**:

| Type | Name | Value |
| --- | --- | --- |
| Secret | `TIKTOK_CLIENT_SECRET` | Client secret выбранного TikTok Sandbox |

Нажмите **Deploy**. Не присылайте секрет в чат, не вставляйте его в код сайта или GitHub. Существующий `PULSE_ACCESS_TOKEN` сохраните: это код доступа к вашему личному API. `YOUTUBE_API_KEY` нужен только для YouTube.

Публичные настройки уже находятся в `wrangler.jsonc`: Client key, Redirect URI, список scopes и `ALLOWED_ORIGIN`. Если Worker имеет другой домен, измените `TIKTOK_REDIRECT_URI` в конфигурации и укажите идентичный адрес в Login Kit.

Проверка версии сервера:

```
https://pulse-api.gromagnetik.workers.dev/health
```

Ожидаются `version: 2` и `tiktokReady: true`. Это подтверждает наличие конфигурации и хранилища, но не корректность секрета и не доступ к аккаунту. Их проверяет настоящая авторизация.

## 4. Подключите аккаунт в Pulse

1. Откройте сайт и обновите страницу, если он открыт давно.
2. В **Подключениях** укажите адрес Worker `https://pulse-api.gromagnetik.workers.dev` и свой **PULSE_ACCESS_TOKEN**. После перезагрузки страницы код нужно вводить снова; это не Client secret TikTok.
3. Создайте собственную группу или выберите существующую в блоке **Подключить TikTok · Sandbox**. Демонстрационные группы не подключаются.
4. Нажмите **Подключить TikTok**. Разрешите всплывающее окно.
5. В окне TikTok войдите в добавленный Target users аккаунт и разрешите запрошенный доступ. Без user.info.basic, user.info.profile и video.list подключение не завершится. Если не предоставить user.info.stats, число подписчиков будет показано как недоступное.
6. Вернитесь в исходную вкладку Pulse и дождитесь подключения. Она должна оставаться открытой; обновление страницы прервет незавершенную сессию. Если предоставлен доступ к другому аккаунту, Pulse попросит подтвердить замену ссылки группы.
7. Внутри группы нажмите **Обновить TikTok** для следующего обновления.

Токены TikTok не передаются в браузер. Группы, показатели и непривилегированный идентификатор подключения сохраняются локально. Код доступа Pulse дает доступ ко всем TikTok-подключениям вашего личного Worker: не используйте эту конфигурацию как многопользовательский сервис с общим кодом.

## Что означают просмотры

TikTok API не возвращает общий счетчик просмотров всех роликов в профиле. Pulse запрашивает до пяти страниц по 20 роликов и суммирует просмотры загруженных видео. В интерфейсе указан этот охват. Если роликов больше 100, это не просмотры всего канала. Сохраненные ранее ролики за пределами текущей выборки остаются со старыми показателями. Превью TikTok временные, поэтому их ссылки обновляются вместе с данными.

Версии одного видео с совпадающей TikTok-ссылкой обновляются без дублирования. Сопоставление разных роликов YouTube/TikTok по названию автоматически не выполняется; ссылки на версии можно объединять вручную при редактировании публикации.

## Отключение

В карточке TikTok своей группы нажмите **Отключить**. Worker сначала отзывает доступ у TikTok и затем удаляет серверную запись токенов. Подключение удаляется из всех локальных групп с этим аккаунтом, а сохраненные ролики и метрики остаются. Если отзыв доступа завершился ошибкой, Pulse покажет ее и сохранит запись для повторной попытки. Также можно отозвать доступ в настройках своего аккаунта TikTok.

Отключение бэкенда в настройках Pulse удаляет только его адрес из браузера и код доступа из памяти. Оно не отзывает TikTok-разрешения; для этого используйте кнопку отключения аккаунта.

## Если появляется ошибка

- **Worker не поддерживает маршруты TikTok**: разверните последние файлы репозитория вместе с `wrangler.jsonc`.
- **TikTok не настроен**: проверьте `TIKTOK_CLIENT_SECRET`, binding `TIKTOK_STORE`, Client key и Redirect URI.
- **invalid client / неверный клиент**: ключ и секрет должны быть от одного Sandbox, а не из разных режимов.
- **redirect_uri**: оба адреса должны совпадать, включая путь, HTTPS и отсутствие завершающего слеша.
- **scope**: проверьте продукты и разрешения в Sandbox, сохраните через Apply changes и повторите авторизацию.
- **Аккаунт недоступен**: проверьте Target users, выбранный Sandbox и аккаунт в окне входа.
- **Сессия истекла**: повторите подключение из исходной вкладки. Незавершенные сессии удаляются через 10 минут.
- **Код доступа Pulse**: вводите значение `PULSE_ACCESS_TOKEN`, а не TikTok Client secret или Google API key.

## Проверки для разработчика

```sh
node --test worker.test.mjs tiktok.test.mjs
node --check app.js
node --check tiktok.js
npx wrangler deploy --dry-run
```

Тесты проверяют повторы callback, привязку сессии, отзыв доступа, ротацию refresh token, границы списка видео и отсутствие токенов в клиентских ответах. Доступ настоящего аккаунта проверяется отдельно после добавления секрета.
